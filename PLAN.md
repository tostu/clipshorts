# Clip-to-Shorts app: plan

Working name: `clipshorts` (placeholder). New app in its own repo. It is seeded by copying the recorder's core (config, SQLite, event bus, Docker, CI) and does not depend on the old projects at runtime.

Target host: low-power server (Intel N100, 4 cores, no GPU, Quick Sync iGPU). Language: German and English.

---

## 1. Decisions already made

- Whole pipeline runs **server-side**. The browser is only a review/override/download UI.
- Layout detection uses **classical CV** (YuNet face detector + rules). No VLM.
- Subtitles use **faster-whisper** (multilingual), rendered as **ASS** and burned in a **single ffmpeg pass**.
- Jobs are **persisted in SQLite** and every stage is **idempotent and cached**, so a restart loses nothing.
- Concurrency is **1 heavy job at a time**, run at low priority so live recordings (later phase) are not starved.
- Feedback after publishing is **manual** (no analytics API).
- Deleted-upstream clips are flagged and blocked at the quality gate.

## 3. Pipeline and artifacts

Every clip gets a folder `data/clips/<id>/`:

```
source.mp4        downloaded clip
meta.json         ffprobe + Twitch metadata (title, channel, game, duration)
frames/           sampled frames (jpg)
layout.json       detected layout + confidence + rects
transcript.json   words with timestamps, language, confidences
captions.ass      generated captions
output.mp4        final 1080x1920 video
```

Stages: `download -> probe -> layout -> transcribe -> captions -> render`.

- Each stage writes its artifact next to a `params_hash`. If inputs and params are unchanged the stage is skipped.
- A layout override re-runs only `render`. A caption edit re-runs `captions` + `render`.
- Startup recovery: any clip left in `running` goes back to `queued`.

## 4. MVP

**Goal:** paste a Twitch clip URL, get a vertical 9:16 video with auto layout and burned-in subtitles.

### In scope

1. Input: Twitch clip URL (`clips.twitch.tv/<slug>`, `twitch.tv/<channel>/clip/<slug>`, `m.twitch.tv/...`).
2. Download with yt-dlp.
3. Auto layout: `fullcam`, `stacked` (facecam over content), `face-focus` (content irrelevant), `content` (no face found).
4. Subtitles: German and English, language auto-detected (clamped to the configured set) or chosen manually.
5. One-pass render to MP4, preview in browser, download button.
6. Layout dropdown override that re-renders (cheap, no re-transcription).
7. Progress per stage over SSE. Job survives restart.

### Out of scope for the MVP

Channel sync, ranking, view tracking, review inbox, quality gate, caption editor, metadata/hashtags, upload, recorder integration, accounts. Optional `AUTH_TOKEN` only.

### API

```
POST /api/clips                 {url, language?: auto|de|en, layout?: auto|fullcam|stacked|face|content}
GET  /api/clips                 list
GET  /api/clips/{id}            status, stage, progress, layout, language, error, output url
POST /api/clips/{id}/rerender   {layout?}
GET  /api/clips/{id}/output     MP4, Range supported (preview + download)
GET  /api/events                SSE: clip state changes
GET  /healthz
```

### Layout detection (MVP algorithm)

1. Sample 8 frames evenly between 5% and 95% of the clip, scaled to 640 px wide for detection (originals kept for cropping).
2. Run YuNet on each frame (score threshold ~0.7). Record face boxes.
3. Classify from the detections:
   - Face in at least 6 of 8 frames, median face area ≥ ~12% of the frame, no small stable corner box: **fullcam**.
   - Face in at least 6 of 8 frames, median face area small (< ~8%) and near a corner, box position stable across frames (IoU high): **stacked**. Facecam rect = face box expanded by a margin and clamped to the frame. Content rect = the rest of the frame.
   - Stacked candidate **and** low frame-to-frame difference in the content region (frame differencing across the sampled frames): **face-focus** (content irrelevant).
   - Face in fewer than 3 of 8 frames: **content**.
4. Write `layout.json` with `type`, `confidence` (agreement across frames, rect stability), rects and notes. Low confidence is shown in the UI.
5. The thresholds above are starting points. Tune them on the fixture clips in M2.

Known MVP limits, fixed in phase 2: expanded-face-box is an approximation of the real facecam border; fullcam uses a static crop around the median face position (no tracking); "content irrelevant" is a motion heuristic.

### Render rules (MVP)

Output 1080x1920, H.264 `yuv420p`, AAC 160k, `+faststart`.

- **fullcam:** crop 9:16 around the median face x, scale to 1080x1920.
- **stacked:** top ~38% = facecam rect (cover-scaled), bottom = content rect (cover-scaled), `vstack`. Split ratio is a parameter.
- **face-focus:** the whole facecam rect fitted to the output width, centered over a darkened, blurred cover copy of the same region (no bars). *Changed after real use:* the original 9:16 crop of the facecam cut off most of the picture and upscaled a corner facecam about 5x. If only a face box exists, a ~4:3 rect of about 3 face widths is used. `low_res_source` is flagged in the render params above a 2.5x upscale.
- **content:** blurred-background fit of the whole frame (the clip editor's "fullscreen" idea).
- Captions: `ass` filter in the same filter graph as the layout. No second encode.
- Audio: `loudnorm` single pass.
- Encoder: `libx264 -preset veryfast -crf 20`. Default output fps capped at 30 to protect the N100. Optional `h264_qsv` via a setting once `/dev/dri` is mounted.
- Progress from `ffmpeg -progress pipe:1`. Timeout scales with clip duration (about 8x), not a fixed number.

### Caption rules (MVP)

- faster-whisper `small`, `int8`, `vad_filter=True`, `word_timestamps=True`, `condition_on_previous_text=False`.
- Language: detect, then clamp to the configured set (`de`, `en`) to avoid false detections. Manual choice overrides.
- `initial_prompt`: clip title, game and channel name from the Twitch metadata (free context).
- Chunking: max 3 words per caption, and **rendered pixel width** at most ~80% of the frame width (German compounds). Break at sentence ends (German abbreviations and ordinals handled, ported from shorts-flow) and at pauses over 0.5s.
- Never split a word across lines. If a line is too wide, reduce the font size.
- ASS style: bold, thick outline, active word highlighted (per-word events), placed in the TikTok safe zone (about 60-65% down the frame, extra right margin).
- A bundled OFL font with full umlaut/ß support is passed via `fontsdir`. No dependency on system fonts.
- Model is unloaded after a few idle minutes to free RAM.

### Status and deviations (as built)

- Code lives in `clipshorts/` (flat package) with 242 tests (3 skip: real Whisper and the libass caption tests when the local ffmpeg lacks `ass`). Old code is kept in `reference/`, gitignored.
- A layout override re-runs only `layout` and `render`: each stage declares the stages whose hashes feed its own (`Stage.after`), so transcribe and captions stay cached.
- The full pipeline runs end to end and ends in `done` with `output.mp4`.
- Auto-detection can pick `face`; a clip with a small corner facecam and irrelevant content correctly renders as face-focus (confirmed on a real clip).
- Repeated `POST /api/clips` for the same slug returns the existing clip (re-queued if it had failed).
- `AUTH_TOKEN` is also accepted as `?token=` because EventSource and media URLs cannot send headers; `/`, `/static` and `/healthz` are public.
- 3-5 face frames out of 8 count as `content` with low confidence (not covered by the original rules).
- `min_font_size` is 30 so very long German compounds shrink instead of overflowing.
- Progress is persisted every 5% for all stages. yt-dlp is pinned (2026.10.26); format `best` already picks the highest premuxed quality for Twitch clips.
- GHCR publish builds amd64 only (the N100 target).
- Known soft spot: a corner facecam of ~460 px upscaled to 1080 px stays somewhat soft. That is a source limit.

### Fixtures and tests

- 5-6 short real clips (kept out of git or trimmed to ~10 s): fullcam, stacked with corner facecam, face-focus case, no-face gameplay, German speech, English speech.
- Pure logic (URL parsing, classifier, chunking, ASS writer, ffmpeg graph strings) is unit-tested with no media.
- One integration test builds a synthetic video with `ffmpeg testsrc` + a tone and uses a stubbed Whisper.
- Whisper and YuNet are never required for the unit-test run.

### MVP acceptance

- A 30 s clip goes from URL to `output.mp4` with no manual step.
- Result plays in the browser, is 1080x1920, captions are readable and German characters are correct.
- Timing on the N100 is recorded. Provisional target: at most ~3 min for a 30 s clip. Set the final target after the M0 benchmark.
- Killing the container mid-job and restarting finishes the job without re-downloading.

## 5. Full feature set (phases after the MVP)

### Phase 1: Channel sync and library

- `channels`, Helix client-credentials token (reuse the recorder's token logic).
- Sync loop per channel: clips by `started_at` window, **download on discovery** (clips are small and can be deleted before you rank them).
- `clip_stats(clip_id, ts, views)` snapshots. Poll densely in the first hours, then back off, stop after ~48-72 h.
- Velocity (views per hour) and peak velocity.
- **Dedupe:** cluster clips of the same moment (`video_id` + `vod_offset` within ~30 s), keep the best.
- Filters: min views, duration range, age window, language.
- **Deleted upstream:** batch-check known IDs, missing twice in a row means deleted. Freeze last known views and velocity, set `deleted_at`, red badge, own filter and ranking bucket (sorted by peak velocity before deletion).
- Library UI: sortable list (velocity, views, newest), thumbnails, "make short" button, optional auto-run for the top N per channel.
- Retention janitor (age/size limits, same idea as the recorder).

### Phase 2: Presets, better layout, caption quality

- **Per-channel preset:** cached layout rects, split ratio, caption style, default language, glossary, fixed hashtags, watermark/credit text.
- A manual layout fix saves back to the channel preset, so later clips of that channel are auto-correct.
- Edge-snapped facecam rectangle (Canny/Hough around the face box) replaces the margin approximation.
- Dynamic face-tracking crop for fullcam (about 5 fps detection, smoothed path applied in ffmpeg).
- Layout editor UI: drag the facecam and content rects, adjust the split ratio, live preview frame.
- Caption polish: 2-second hook text overlay, emphasis on key words, emoji option.
- LLM caption correction (German prompts, `gemma3`-class model via Ollama or an API) using the shorts-flow `align_script_to_whisper` approach: the LLM fixes the text, Whisper keeps the timing.
- Glossary-driven Whisper prompts per channel.

### Phase 3: Quality gate and review inbox

The gate runs after render and stores a `pass | warn | fail` JSON verdict on the short.

| Check | Method | Level |
|---|---|---|
| Format 1080x1920, 15-60 s, codec | ffprobe | hard |
| Loudness, long silence, clipping | ffmpeg `ebur128`, `silencedetect` | hard if mostly silent |
| Black or frozen frames | `blackdetect`, `freezedetect` | soft |
| Face visible in the **rendered** output | YuNet on 3 output frames | soft |
| Captions fit (line count, min font size, safe zone) | ASS wrap result | hard on overflow |
| Transcript confidence, speech ratio | Whisper `avg_logprob`, `no_speech_prob` | soft |
| Profanity / slurs | DE+EN word lists | configurable |
| Duplicate or already published | perceptual hash vs earlier shorts | hard |
| Metadata sane (length, tag count, language match) | rules | soft |
| **Clip deleted upstream** | `deleted_at` set | hard, override needs a reason |

Rules: pass can export; warn needs an acknowledgement; fail needs an explicit override with a logged reason. Auto-approve on all-green is a per-channel option, off by default.

Review inbox: card feed of rendered shorts with approve / reject / edit, keyboard shortcuts, side-by-side original vs result. Caption timeline editor (port the clip editor's `SubtitleTimeline` and crop editor ideas) with partial re-render by stage.

### Phase 4: Metadata and export

- LLM metadata with structured output (JSON schema, `keep_alive: 0` to free RAM): title/hook, caption, hashtags. Mix of fixed channel tags and clip-specific tags. Per-platform variants (TikTok caption, YouTube Shorts title). Input: transcript + clip title + game + channel.
- Manual export: download MP4, copy caption + hashtags.
- "Mark as published" with URL and platform.
- **Manual feedback** per publication: platform, URL, views at 24 h (optional), rating (good / ok / flop), note. A simple table of channel x layout x rating is the only reporting.
- TikTok "upload to inbox" (draft) via the Content Posting API. Direct posting is restricted until TikTok audits the app, so verify the current rules before building. YouTube Shorts and Instagram Reels behind the same `Exporter` interface. Scheduling queue after that.
- Rights: per-channel "approved" flag and an optional credit watermark.

### Phase 5: Recorder fusion

- Move the recorder in as a module. Channels, settings, SSE bus and janitor are shared.
- A clip is a pointer (`video_id` + `vod_offset`). When the stream was recorded, **cut from the own recording** for source quality, and extend the start/end to sentence boundaries (clips often start mid-word).
- Chat logging during recording. Message-rate spikes and emote spam produce highlight suggestions for moments nobody clipped.
- Shared storage budget and retention across recordings and clips.

### Phase 6: Extra sources and formats

- Story mode from shorts-flow (Reddit text -> TTS -> background gameplay) as a source plugin. TTS engines stay in isolated venvs or containers.
- Multi-part split for long content (`split_evenly` logic).
- Compilations of several clips.

### Cross-cutting (grows through the phases)

- Auth: `AUTH_TOKEN` first, real login only if the app is ever exposed beyond the VPN.
- Observability: structured logs per clip, stage timings stored, error taxonomy visible in the UI.
- Backups: SQLite + presets export.
- CI: tests and Docker publish on every push.

## 7. Risks and open decisions

| Item | Risk / decision |
|---|---|
| yt-dlp and Twitch | Twitch changes often. Pin the version, add a smoke test, keep a fallback download path ready. |
| N100 speed | Estimates only. M0 benchmark decides the Whisper model size, fps cap and whether Quick Sync is needed. |
| Layout accuracy | Heuristics will misclassify some channels. Presets (phase 2) are the real fix; the override dropdown is the MVP safety net. |
| Whisper code-switching | German speech with English gaming slang gets transliterated. Mitigate with glossary, LLM correction and the caption editor. |
| TikTok API | Audit requirements for direct posting. Verify before phase 4 design is final. |
| Rights | Re-uploading other streamers' clips can conflict with TikTok originality rules and streamer rights. Per-channel approval flag and credit watermark are in phase 4. |
| Secrets | `reference/ai-twitch-clip-editor-main/backend/.env` was not opened and `reference/` is gitignored. If it holds real secrets, never copy it into the new repo and rotate if it was committed. |
| App name | Still a placeholder. |
